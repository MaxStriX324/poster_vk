# poster_vk — отложенные публикации ВКонтакте

Исторический Python-проект автоматизации публикаций в сообществе ВКонтакте. Бот принимает сообщения от двух разрешённых пользователей и создаёт отложенные записи с заданным интервалом. Исходный код сохранён как пример ранней автоматизации; **актуальная работоспособность с API ВКонтакте и современными версиями библиотек не подтверждена**.

## Что реализовано в коде

- Получение событий сообщества через VK Bot Long Poll (`vk_api`).
- Приём сообщений от двух разрешённых пользователей (`user_id1`, `user_id2`).
- Обработка текста и фотографий; загрузка изображений в альбом сообщества.
- Планирование публикаций через `wall.post` с `publish_date`.
- Хранение очереди и служебных полей публикаций в SQLite (`posts`).
- Уведомления в указанную беседу о публикациях, вступлениях/выходах из группы и комментариях.
- Команда `тест` или `Тест` для сообщения о количестве отложенных записей.

## Устройство

- `main.py` — обработчик событий, работа с VK API, очередью и SQLite.
- `settings.ini` — параметры авторизации и расположение файлов.
- SQLite-база, обозначенная в настройках как `dbposter.db`, **не включена в репозиторий**. Код обращается к таблице `posts`, но автоматическое создание схемы в `main.py` не обнаружено.

## Настройка (для изучения и восстановления)

1. Установите Python и зависимости, импортируемые `main.py`:
   ```bash
   python -m pip install vk_api requests
   ```
2. В `settings.ini` укажите `username`, `password`, `group_token`, `group_id`, `album_id`, `chat_id`, `user_id1`, `user_id2`, `path_to_photo`, `time_beth_post` (интервал **в секундах**) и `path_to_bd`. Названия ключей оставлены в точности как их читает программа.
3. Подготовьте каталог для фотографий и SQLite-базу с таблицей `posts` согласно обращениям в коде. Схема и миграции сейчас не документированы, поэтому запуск на пустой базе может завершиться ошибкой.
4. При наличии корректной базы и разрешений API историческая точка входа:
   ```bash
   python main.py
   ```

**Безопасность:** `settings.ini` отслеживается Git и может содержать пароль пользователя и токен сообщества. Не коммитьте его после заполнения настоящими секретами. Для эксплуатации следует перенести секреты в переменные окружения или локальный файл, исключённый из Git.

## Ограничения

Этот README описывает **имеющийся код**, а не подтверждённую современную установку. Проект использует авторизацию аккаунта по логину и паролю, устаревающие методы VK API и собственную структуру SQLite; для безопасного повторного запуска необходимы проверка прав, актуализация авторизации, миграция схемы и тестирование на тестовом сообществе. Автоматических тестов и готового установщика в проверенной части репозитория нет.

## Статус

**Legacy / архивный проект.** Для новых задач в приоритете более безопасная авторизация через токены, проверяемые зависимости и явная инициализация базы.
